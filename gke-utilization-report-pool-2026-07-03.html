Method. Per app, pods are combined with agg=pool (all pods’ raw points pooled into one distribution). low is the smallest value still > 0; p90/p95/high use the nearest-rank method over the combined series. Suggested sizing = basis ÷ target, as a % of the current configured value: request uses p95 with target 0.8; limit uses peak with target 0.9. Utilization is a per-pod ratio, so avg/pool map directly to per-pod sizing; sum inflates by the concurrent replica count.
To set YAML: current values were read from yaml/<app>.yaml, so the suggested column holds absolute values ready to paste (suggested = used ÷ target × current). A machine-readable table is written alongside as gke-utilization-report-pool-2026-07-03.apply.csv.
Caveat: memory is incompressible — the "peak" here is the max over the 2026-06-26T12:33:00.000Z…2026-07-03T12:32:00.000Z window; leave extra headroom on memory limits to avoid OOMKills.
